# P0-004 research and protocol decisions

Reviewed 9 November 2026. This is an implementation decision record; vendor documentation is not evidence that the hosted Twin configuration works. No new runtime package or server was installed. Existing TypeScript, Zod, jose, Web Crypto, Workers, D1 and the bounded P0-003 executor are reused.

## Reliability choices

- **Idempotency:** owner/generation-scoped proposal key binds the full proposal; changed input conflicts. Execute wins a single compare-and-swap transition before admission. Existing run/call uniqueness remains intact.
- **Durable continuation:** immutable, checksummed plan and source references in D1; no hidden conversational transcript or stored JWT. Resume reads the current account and prior receipts. Unknown/failed work returns to review; approval is never inherited indefinitely.
- **Deadlines:** workflow expiry is at most seven days, authorization at most five minutes or identity expiry, execution at most 45 seconds with the existing two-second audit reserve. D1 orchestration awaits are individually bounded at five seconds. A disconnected client may not cancel a noncooperative provider; SQL guards prevent late authoritative completion. Explicit cancel is persistent and works across requests.
- **Retries/circuit behavior:** three explicit read attempts maximum, existing account quotas and provider deadlines. A global circuit breaker is not justified for one configured provider at this alpha scale; no process-local counter is presented as a distributed circuit breaker. No external-effect tools exist.
- **Reconciliation:** compare owner/generation, authorization, plan, run, individual receipts, persisted outcome digest and transition continuity. Missing records yield `CANNOT_PROVE`; contradictions yield `DIVERGENT`. `VERIFIED` means the bounded read was recorded consistently, not that a model's prose is true or an email was sent.
- **Trust boundary:** Worker and D1 are jointly trusted. A checksum detects corruption against retained records but cannot defeat an administrator who rewrites all evidence. No independent receipt signing, external attestation or tamper-proof ledger is claimed.
- **Fault injection:** retain existing signed-JWT and real local workerd/D1 tests. Extend them with workflow CAS, rollback, cancellation, deletion, invalid checkpoints and evidence faults. Keep all hosted and real-model gates separate.

The optional exporter and native adapter are deliberately inactive by default. Benchmark results describe local instrumentation only; they do not justify adding a backend or predict Cloudflare latency.
